# SpiderBot CAD adapter — Huna Robo (provisional)

## Status

This folder is an integration scaffold, **not a validated print package**. The exact Huna Robo controller/board model is still unknown. Do not print the tray or assume the upstream SpiderBot parts fit the existing XZORT dragon-lizard assembly.

## Servo baseline decision

Use **MG90S, 180-degree positional micro servos with metal gears** as the initial reference *only if adapting the original lightweight SpiderBot geometry*. Plan for 12 identical servos so all joints share a consistent envelope and calibration approach.

Why this baseline:
- The upstream SpiderBot README explicitly lists SG90/MG90S servos and a 12-DOF configuration.
- MG90S metal gears are a more sensible wear-resistance baseline than a plastic-geared SG90 for repeated leg motion.
- This is not a guarantee of sufficient torque for the current large dragon-lizard body. The existing CAD has a much larger body/envelope and must not be treated as mechanically compatible with MG90S without a mass/lever-arm assessment. If retaining that body, choose a higher-torque servo only after recalculating joint loads and redesigning mounts.

Before CAD is finalized, confirm the exact MG90S variant/dimensions from the selected vendor or measure the physical unit. Unlabelled clones may differ. Do not buy 12 until a single servo and its mounting interface have been checked.

## Upstream reference

- Source: https://github.com/shashikant-io/Project-Spider-Robot
- Upstream README describes a 12-DOF quadruped built around ESP32 + PCA9685 and 12 SG90/MG90S servos.
- Its listed STL names are `body_d.stl`, `body_u.stl`, `coxa_l.stl`, `coxa_r.stl`, `femur_l.stl`, `tibia_l.stl`, `tibia_r.stl`, and `s_hold.stl`.
- The upstream repository did not expose a clear license in the reviewed README/repository view. This project therefore links to the source instead of copying its STL binaries into this repository. Confirm permission/license before redistributing geometry.

## Tray design contract

`huna_board_tray.scad` is parametric and intentionally refuses to render while required dimensions are unset. It does not guess the board footprint or mounting pattern. Once the exact Huna Robo board is identified, measure:

1. PCB width and length (mm), excluding cable bend space.
2. PCB thickness and maximum component height.
3. Mounting-hole centre spacing and hole diameter, if the board has holes.
4. Port/connector positions and cable exit directions.
5. Required access to reset, USB, switches and terminals.
6. Servo dimensions and horn/mounting interface from the chosen physical MG90S unit.

The tray is intended to be removable from the robot body. Choose fastener locations only after the current body CAD's available mounting points and clearances have been checked. Leave connector and wire bend clearance; do not route servo power through a controller board unless its specification explicitly supports it.

## Power and stability gate

The 12 servos need a dedicated, adequately rated servo supply; do not power the servo rail from the controller's 3.3 V regulator. Share signal ground correctly and verify current requirements from the actual servo datasheet before choosing the supply. The servo driver, controller, battery and wiring must be finalized together.

## Integration gate

Before exporting final STL:
- identify the Huna Robo board from official documentation or physical measurements;
- confirm exact servo variant and physical mounting dimensions;
- set the SCAD parameters and hole pattern from measured dimensions;
- verify the tray against the robot body envelope and adjacent parts;
- render/export, inspect the mesh, and document the measured envelope;
- do a physical fit check before treating it as competition-ready.

No STL is generated by this scaffold. No dimensional, torque, collision, or print-fit verification is claimed.
