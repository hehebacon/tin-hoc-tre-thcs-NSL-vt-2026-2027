# Robot Core Architecture\n\n## Autonomous Core\n\nThe firmware now has an offline mission-level decision layer above locomotion.\n\nArchitecture:\n\nSensors -> RobotCore -> DecisionEngine -> MotionSafety -> MotionController -> GaitController -> IK -> calibration -> PCA9685 -> 12 servos\n\nDecisionEngine receives state feedback from sensors through RobotCore. It chooses the next high-level action; it never writes PWM or raw servo angles.\n\n## Offline decision engine\n\n`DecisionEngine` is deterministic C++ firmware. It does not use an AI API, Internet connection, cloud service, or token.\n\nExample:\n\ngoal RESCUE -> SEARCH -> target detected -> RESCUE -> rescue complete -> RETURN_HOME\n\n## Goals\n\n- RESCUE\n- PATROL\n- RETURN_HOME\n- DEMO\n\n## Actions\n\n- IDLE\n- SEARCH\n- APPROACH\n- RESCUE\n- RETURN_HOME\n- PATROL\n- DEMO\n- FAULT\n\n## Serial commands\n\ngoal RESCUE\ngoal PATROL\ngoal RETURN_HOME\ngoal DEMO\nfound\nrescue_done\nhome\nai_status\nreset_mission\n\nJSON example: {"command":"GOAL","goal":"RESCUE"}\n\nExisting low-level mission and gait commands remain available for testing.\n\n## Feedback loop\n\ngoal -> decision -> motion -> sensor reading -> decision again\n\nA target detection is latched so a brief sensor detection is not immediately lost.\n\n## Safety\n\n- MotionSafety has priority over the decision engine.\n- E-STOP disables motion.\n- Motion timeout enters E-STOP.\n- Sensor sanity violations can move RobotCore into FAULT.\n- A mission cannot start while motion safety is blocked.\n- The decision engine cannot bypass servo calibration or MotionSafety.\n\n## Current boundary\n\nThis is an offline autonomous decision layer, not a general-purpose generative AI.\n\nReal autonomous navigation still requires physical perception and localization. Simulator path planning must not be presented as proof that the physical robot can navigate without those sensors.\n\n## Development rule\n\nKeep the architecture modular: Mission/Decision -> MotionController -> Kinematics -> Calibration -> Servo driver.\n\nThis allows simulator and future hardware backends to share the same mission logic.

## AI + Perception extension

The core is extended with a Perception layer that normalizes sensors into WorldState. WorldState feeds the deterministic DecisionEngine. An optional OnlineAIClient can provide Gemini-based operator assistance over Wi-Fi, but it never bypasses RobotCore or MotionSafety.

Flow:
Sensors -> Perception -> WorldState -> Offline DecisionEngine -> RobotCore -> MotionController

Optional:
Web UI -> OnlineAIClient/Gemini -> advice -> operator/validated command -> RobotCore

Wi-Fi uses AP + optional STA so local control remains available when Internet is unavailable.
