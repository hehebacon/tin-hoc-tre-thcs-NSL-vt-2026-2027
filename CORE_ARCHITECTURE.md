# Robot Core Architecture\n\n## Core V4\n\nThe firmware now has a mission-level control layer above locomotion.\n\n```text\nSensors\n  ├─ Camera\n  ├─ Thermal\n  ├─ IMU\n  └─ Environmental\n       ↓\n   RobotCore\n   ├─ mission state\n   ├─ detection latch\n   ├─ sensor sanity checks\n   ├─ fault transition\n   └─ mode → gait policy\n       ↓\n MotionSafety\n       ↓\n MotionController\n       ↓\n GaitController\n       ↓\n IK → calibration → PCA9685\n```\n\n## Mission modes\n\n- IDLE\n- PATROL\n- SEARCH\n- RESCUE\n- RETURN_HOME\n- FAULT\n\n## Serial commands\n\n```text\nmission IDLE\nmission PATROL\nmission SEARCH\nmission RESCUE\nmission RETURN_HOME\n\nfound\nhome\nmission_status\nreset_mission\n```\n\nJSON:\n\n```json\n{"command":"MISSION","mode":"SEARCH"}\n```\n\nThe existing gait commands remain available for low-level motion testing.\n\n## Safety behavior\n\n- E-STOP disables gait and latches the firmware safety state.\n- Motion timeout enters E-STOP.\n- Sensor sanity violations can move the core into FAULT.\n- A mission cannot start while motion safety is blocked.\n- Detection is latched until mission reset.\n\n## Current boundary\n\nThe mission core is a deterministic state machine. Real autonomous navigation still requires physical perception and localization drivers. The simulator contains the A* path planner; the ESP32 should receive validated navigation targets rather than inventing a position from missing sensors.
